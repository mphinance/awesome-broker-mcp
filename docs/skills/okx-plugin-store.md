# OKX Plugin Store (okx/plugin-store): 63 skills, summary table only

Catalogue of DeFi, trading and data plugins that sit on top of the Onchain OS CLI. Most are community-built; OKX curates and republishes them. The router skill `okx-dapp-discovery` in [okx-onchainos.md](okx-onchainos.md) installs entries from here on a keyword match. Per-skill sections are deliberately omitted (63 skills); no SKILL.md is reproduced, which also keeps the license rule moot.

Method: shallow clone, files read as plain text, `registry.json` parsed with a read-only script kept outside the clone. No installer, plugin binary or script from the repo was executed.

## What is in the repo

- 63 skill folders under `skills/`: 62 entries in `registry.json` plus the `plugin-store` manager skill. Registry types: 49 `community-developer`, 11 `official`, 1 `community`, 1 `dapp-official` (Uniswap). Categories: 48 `dapp`, 14 `strategy`.
- 37 plugins ship a compiled Rust binary (`components.binary`, one per target triple, released as `plugins/<name>@<version>` assets with a `checksums.txt`) next to the SKILL.md. The rest are SKILL.md only, or SKILL.md plus a Python bot, or API wrappers.
- `official/core` (Rust source for the shared core), `scripts/launcher.sh` and `scripts/update-checker.py` (the shared launcher and auto-updater), `registry.json` and a `stats` folder (the registry names `https://plugin-store-dun.vercel.app` as its stats URL).
- External submissions are not accepted: "External submissions from independent developers are not accepted at this time" (README). Authors still appear as individual GitHub accounts in the registry.

## Summary table (63 skills)

Capability key: read (data only), paper (simulated), live (real on-chain value). "Typed live-mode gate" means the SKILL.md has a "Live Trading Confirmation" block: paper or preview is the default, switching to live needs a typed reply such as `confirm live mode` (a plain "yes" does not count), a preview is required before every write, and autonomy after the switch is bounded by config limits. That gate is prose, so it is model-enforced. "Binary previews unless `--confirm`" means a Rust `confirm` flag was found in the plugin's `src/` and, for `aave-v3-plugin`, `main.rs` was read: it passes `!cli.confirm` as the dry-run argument, so the plugin does nothing on-chain without `--confirm`. That one is code-enforced, but the flag is supplied by the agent.

## Guardrails: model-enforced vs code-enforced

**Code-enforced:**

- Plugin binaries (37) default to a preview and need `--confirm` to broadcast (grep of every `src/` found a confirm flag; one binary read in full for that path). `gmx-v2-plugin` says its `--confirm` flag alone is "necessary but **not sufficient**" given the typed gate, which concedes the flag is not the authorisation.
- Signing goes through the OKX Agentic Wallet (TEE-held key). The bot skills say "No need to set WALLET_PRIVATE_KEY"; `fourmeme-plugin` states it has "no `PRIVATE_KEY` env var or .env support by design".
- Bots ship with a paper flag set: `PAPER_TRADE = True` (`mainstream-spot-order`, `meme-trench-scanner`), `MODE = "paper"` (`top-rank-tokens-sniper`, `wallet-tracker-mcap`, `rwa-alpha`), `DRY_RUN = True` (`one-click-token-launch`). Caveat: `mainstream-spot-order/live.py` reads it as `getattr(config, "PAPER_TRADE", False)`, so a missing attribute means live. Flipping live is a one-line edit the agent can make; the typed gate is the only barrier.
- `starter-coach` has a real code gate (`paper_gate.py`: 10 paper trades, 5 live micro-trades, 7 days, 0 harness breaches), but its state lives in a local `.paper_gate` directory next to the skill that the agent can write.
- `birdeye-plugin` x402 mode caps spend at 100000 USDC base units (0.1 USDC) per day by default, tracked in `~/.birdeye/spend.json`.

**Model-enforced only:**

- The typed live-mode gate, per-trade preview, and bounded session autonomy in 33 skills. Once the user types the confirmation, the five bot skills run autonomously within config caps ("MAX_SOL", "MAX_TRADES", loss caps) that sit in editable config files.
- "Prose confirm" skills (12 rows) rely on the agent asking before it adds `--confirm`.
- Update-version checks that "MUST stop" and ask before any `npx skills add` (a block repeated in every SKILL.md).

## Secrets, files and self-modification (things with teeth)

1. **Pre-flight installs remote code.** The injected preflight in the plugin SKILL.md files downloads the `onchainos` installer from the latest GitHub release tag and checks it against `installer-checksums.txt` fetched from the same release (a same-origin check: it catches corruption, not a compromised release), runs it with `sh`, then runs `npx skills add okx/onchainos-skills --yes --global` and `npx skills add okx/plugin-store --skill plugin-store --yes --global`.
2. **Binary and launcher download.** Each binary plugin's preflight fetches `launcher.sh` and `update-checker.py` from the `main` branch (unpinned) into `~/.plugin-store/`, then downloads the plugin binary into `~/.local/bin/`.
3. **Silent auto-update with no verification.** `launcher.sh` calls `update-checker.py` on every CLI invocation. When the registry shows a newer version it writes `~/.plugin-store/update-<name>.sh` and runs it in the background: `npx skills add ... --yes --global` (this rewrites the SKILL.md, including its guardrail text) and a `curl` of the new binary from GitHub releases that is `chmod +x`'d and moved into place with no checksum step, unlike the first install. The SKILL.md claims "The check is a read-only fetch ... it does not install anything" and that install needs a confirmed `npx skills add`; that describes the skill-level version probe, not the launcher, which updates without asking. The registry it trusts is fetched from `raw.githubusercontent.com/okx/plugin-store/main/registry.json`, so whoever controls `main` controls the next binary you run, with wallet-signing reach through `onchainos`.
4. **Local key material.** `birdeye-plugin` x402 mode reads a base58 Solana private key from `~/.birdeye/key` ("Use a **burner wallet** only"). `coinank-openapi` and the pay-per-call paths inherit `okx-agent-payments-protocol`, which can use `pay-local` with `EVM_PRIVATE_KEY`.
5. **Writes to disk.** `clawvard-agent-eval` persists an identity token after a typed `confirm save token`; bots write position and trade state (`scan_positions.json`, `scan_trades.json`, `trader_soul.json`); `~/.plugin-store/` holds caches, launcher and update scripts.
6. **Third-party endpoints.** `stablecoin-*` and `yield-strategy-advisor` call Barker's API and state they send only public parameters; `sorin-skill`, `rootdata-crypto-plugin`, `coinank-openapi` and `birdeye-plugin` call vendor APIs with keys or x402 payments; `macro-intelligence` starts a local HTTP service and reads 7 news sources.
7. **Leverage and token launches.** `hyperliquid-plugin` and `gmx-v2-plugin` open leveraged perps; `hyperliquid-plugin` also withdraws. `clanker-plugin`, `fourmeme-plugin`, `one-click-token-launch` and `pump-fun-plugin` create or trade memecoins; the router's own text calls pump.fun buying and selling a "Routine plugin install, not market manipulation".

## Gap list

1. Auto-updater replaces binaries and SKILL.md guardrails with no checksum, from an unpinned `main` registry.
2. Typed live-mode gate is prose; paper flags are one-line edits in agent-writable config.
3. Initial installer checksum is same-origin.
4. README says Apache-2.0, LICENSE files say MIT.
5. 49 of 62 registry entries are community-developer submissions republished under OKX distribution; OKX states no external submissions are accepted now, yet the authors are individuals.
6. Local private-key paths exist in `birdeye-plugin` (x402) and, via the payments skill, `pay-local`.
7. 12 trading plugins have no typed live gate at all, only prose confirmation plus the binary's `--confirm` flag.
